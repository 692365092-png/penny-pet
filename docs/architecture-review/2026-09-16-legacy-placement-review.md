# v10 位置只作为旧文件输入

本节点接续远端 `d531854101b359deb57b5cc46a435a78adfc6229`。已确认此前五个节点
均已进入该分支；本次基于包含另一轮审查合并的最新代码继续工作。

## 发现与改动

此前窗口事实接收器每次接受 HWND 回执，都会把实际像素投影为 v10 的
`DisplayId / LocalLogicalX/Y/Width/Height`，再写回模型。随后旧文件迁移又从这组
字段建立 Preferred。这不仅维持一份重复位置，还有可复现的顺序问题：迁移前收到的
窗口回执会覆盖文件原值，最终迁移的是当前临时位置，而不是存档记录的意图。

现在删除这五个可变字段，文件入口将其读取为不可变的 `StickyLegacyPlacement`。
窗口回执仅更新实际事实和现有物理恢复副本，不再读取或改写待迁移值。解析、尺寸修复
只在 Codec 发生；成功迁移或接受用户位置提交后消费旧输入。目标屏幕暂缺时，仍允许
未迁移输入经过保存、重启继续保留。持久化克隆可以共享不可变值，之后 live 模型的
迁移不会改写已捕获的保存快照。

有 Preferred 时，恢复只遵循该偏好；目标屏缺失则使用现有物理恢复路径。不会因为
旧 GDI 名恰好还能解析，就重新启用更早的 v10 坐标。已有 v11 文件即使同时携带旧
输入，也不再让它参与这一选择。文件仍保持 v11 的 37 个字段及 v1–v11 读取能力；
未迁移输入原样表达，已消费输入的兼容栏写空 ID 与四个 0。

同时删除 `StickyCanonicalPlacement` 及没有生产调用者的“在宠物旁生成”算法。
新建便签沿用现有工作区居中规则，直接产生像素矩形；坐标转换函数只返回逻辑矩形，
不会为了换算制造另一个可写持久化模型。新建诊断也在拼接字符串前检查开关。
