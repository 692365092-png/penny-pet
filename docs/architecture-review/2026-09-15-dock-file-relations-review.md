# 从运行时模型删除旧 Dock 父链

接续 `48af620`。本节点处理 PC-6 / PC-8 中旧父链仍暴露在运行时模型的问题。

`StickyNoteData.DockParentId` 已删除，持久化克隆不再复制它，运行时分组和清除成员
也不再维护或清空它。唯一关系仍是 `DockGroupId / DockGroupOrder`，隐藏成员继续占据
组内槽位。运行时 `StickyDockGroups` 从 208 行缩为 79 行，只保留当前关系的查询、
排序和修改。

旧格式兼容由 `StickyDockFileRelations` 负责。Codec 通过单独的输出参数给文件读取者
提供旧父 ID；读取者在本次加载的局部字典中暂存，完整读取后转换为当前组关系。
旧字典不会进入 repository 字段、窗口消息、写入快照或模型克隆。文件写出从当前组
顺序推导第 22 号旧字段，不改变 live model。正常加载、严格抢救、备份导入走相同的
迁移规则；显式组优先于旧边，损坏的环或分叉仍使用确定性的恢复顺序。

这里发现并修复了一个既有导入缺口：`StickyImportBackupValidator` 原先逐行解析后
直接返回，尚未迁移 v7 的父链。合并规划器只识别当前组关系，因此无法正确判断一个
旧组是否已有成员存在于当前数据中。现在完整验证后立即迁移，再进行冲突合并：
完整旧组保持顺序和隐藏槽位，部分重复导入的新成员按现有产品规则脱离原组，当前
便签的内容、位置和可见性保持不变。

同时删除两处不需要的重复工作：验证器不再克隆刚解析、尚未共享的每张便签；从旧
目录迁移时，直接接收已经由 `LoadFromFile` 完成修复、排序和关系迁移的数据，不再
重复 Repair / Normalize。保存格式仍为 v11，v1–v11 历史夹具和损坏输入边界保留。

新增 7 个实际行为用例，覆盖 v7 / v11 父链备份、部分重复导入、显式单成员组与旧边
冲突、普通文件和旧目录中重复行的首条优先规则，以及严格抢救后的兼容写出与重启。
原有测试改为从文件边界注入冲突父链、检查原始输出字段，不再给模型塞入不存在的旧
字段。Windows 自测中的“坏父链不影响组快照”也改为验证真实备份解析入口。

验证：550 次实际 MSTest 方法 / DataRow 调用通过，0 失败；Core、测试、Windows Core
和 SelfTests 按项目边界编译通过，警告视为错误。Windows GUI 自测未在 Linux 上运行。

旧父链的运行时类型隔离在此完成。PC-3 的物理 / v10 / Preferred 几何字段仍在模型中，
本节点没有把关系字段的删除算作几何债务结案；同样不代表全部 Dock 恢复与拓扑流程
已经合并成单一状态机。
