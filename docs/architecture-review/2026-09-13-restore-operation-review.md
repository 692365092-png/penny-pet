# 整组恢复：一个操作身份，一次 STA 恢复命令

本轮继续 PR #4，以上一轮已验证的 `410dc4f` 为比较基线。`349af93` 是实施中途的 WIP 保全检查点，本文和配套证据记录补齐回归后的结果。范围是具有完整 preferred 几何的普通整组恢复，以及它与 topology、取消、窗口登记和删除的边界。

## 从用户行为确定事务边界

用户点击隐藏成员，希望整个组在正确的屏幕和尺寸下出现；失败时，原本已经可见的成员不应被一起关闭。恢复尚未完成时收起、删除、退出或切换显示器，旧回调不能重新显示窗口，也不能释放后来那次恢复的占用。

原实现把一个操作拆成 N 次 EnsureSession、N 个 Pet 回调、一个可变计数器，再在最后一个回调里重新迁移偏好、重新读取 topology、构造布局并发送 reproject。另一个 HashSet 记录组是否忙，终止分支负责释放它。这里大部分状态来自线程往返的实现方式，并非用户需求。

## 逐层发现与实际修改

| 层次 / 操作 | 原问题 | 已实施的变化 |
| --- | --- | --- |
| 失败体验 | `FailHostedDockRestore` 对整个组 RemoveNote / Close / Visible=false，包括恢复前已经可见的成员 | 原生恢复失败时保留已有回滚，只关闭本次新建的窗口；Pet 不再把整组当作新建失败一起关闭 |
| 调度 | N 次准备命令和 N 个回调仅用于汇合后执行一次布局，计数、错误和失败成员分散在 PetForm | 普通恢复改为一个 `RestoreDockGroup` 命令，在 Sticky STA 内完成准备、放置和显示，再返回一个完整结果 |
| 操作身份 | HashSet 只表示组被占用，无法区分旧回调与后来恢复；准备对象持有可变原模型引用 | `DockRestoreOperations` 直接登记具体 `DockRestoreOperation`；回调先验证同一对象，再验证成员身份、顺序、组关系和开始时可见性 |
| 几何选择 | 准备前、准备后重复迁移和读取当前状态，布局的输入时间不清楚 | 恢复操作捕获 detached 内容快照、preferred 布局、目标屏幕与 topology；原生阶段按目标 HWND 实测 DPI 生成物理计划 |
| topology 变化 | 普通恢复与 `_pendingDockTopologyGroups` 使用独立占用表，可能向同一组下发竞争计划 | 正在普通恢复的组跳过独立 topology reproject；新代 topology 取消旧恢复并从当前成员发起新操作，旧代回调不能提交 |
| 快速取消与重新展开 | 清空 Pet 引用不能撤销已排队的原生命令；已执行显示还可能晚于收起 | 操作携带 CancellationToken；原生入口和提交显示前检查取消。Pet 在替代命令之前排队隐藏原来隐藏的成员，覆盖“原生刚完成、Pet 尚未收到结果”的窗口 |
| 会话序号 | 原来依赖逐窗 EnsureSession 回调先登记租约；合为一个命令后，新窗口序号可能低于旧 HWND 的序号 | 整批结果携带实际创建标志；完整结果检查通过后才注册或重置新会话，既有会话仍必须越过当前水位，不能借恢复降低 sequence |
| 恢复中删除 | Pet 尚未登记并不代表 STA 没有 HWND，直接从 repository 删除可能遗留隐藏窗口 | 删除统一等待原生 Close 确认；窗口不存在时 Close 成功，IME 编辑时仍拒绝关闭；窗口线程退出后也可确认其 HWND 已不存在 |
| 保存和完成 | 普通恢复中迁移、布局回写、可见性完成有重复保存，含 UI 同步 Save；外围异常还可能触发几何失败清理 | 迁移和需要持久化的恢复完成进入现有异步 writer；恢复结果复用整批接收但不在那里再次保存。成功释放操作身份后才刷新 UI 和请求焦点 |

## 当前职责边界

- `DockRestoreOperation` 拥有不可变恢复意图：成员、内容快照、目标、布局、捕获 topology 和取消。`DockRestoreOperations` 是这些操作的注册表，没有另存一份 busy 状态。
- `StickyUiHost.RestoreDockGroup` 拥有 STA 内的准备和本次创建资源清理；复用现有 `ApplyDockGroupReproject` 的 DPI 探测、批量放置、显示与回滚。
- Pet 只有一个恢复结果入口，先核对操作、成员和整批事实，再更新 canonical / Effective / session lease。失败清理与成功后的焦点请求不再共享一个“任何异常就关闭整组”的分支。
- `StickyHostedRuntime` 继续拥有会话登记与 sequence。新增批次接收方法集中处理“新会话可建立新基线、已有会话不可降低水位”。主文件 writer 沿用前轮实现。

移除了 `HostedDockRestorePreparation`、准备计数、准备失败字段、独立组占用 HashSet、legacy IDs 拼接锁键，以及 Prepare / Placement / PostReproject / ReprojectCompleted / Success / Fail 多层恢复转发。共同 preferred 屏幕选择也不再放在 PetForm 中。

这些类没有把 PetForm 的私有方法换个文件再调用：恢复计划可独立构造与验证，操作可独立取消和退休；STA 收到的是一个完整请求。Pet 仍保留实际模型提交和 UI 接线，这部分不能宣称已经全部迁出。

## 可证明的规模和调度变化

以 `410dc4f` 为基线，两个 PetSticky partial 合计从 4509 行降到 4142 行，其中窗口 partial 从 3054 行降到 2687 行。新增恢复操作及注册表为 183 行；计入宿主、协议和登记逻辑变化后，生产 C# 净减少 91 行，不含测试和文档。

N 个成员的普通恢复从 N 个准备命令和一次放置命令，变成一次主恢复命令和一个结果回调。成功后的焦点及尺寸角色更新仍有各自命令，取消时仍有必要的隐藏补偿；没有把它们算成消失。窗口创建和布局仍是 O(N)。没有 Windows 延迟测量，不宣称“最高性能”。

## 行为证据

[restore-operation-evidence](restore-operation-evidence/README.md) 保存具名结果、源码哈希和构建日志。

- 464 次真实 MSTest 方法 / DataRow 直接调用通过，0 失败；其中 119 项标记为源码边界检查。
- 新增 23 个行为用例：实际目标 DPI 下的根宽度及独立高度、detached 输入、缺屏和偏好屏返回、输入不完整、删除 / 重排 / 重组 / 模型替换、重复恢复、旧完成、取消 token、新窗口重建 sequence、已有窗口的较新事件，以及取消后已有隐藏 HWND 的重新登记。
- 迁移原来的恢复源码边界，并增加一个删除边界检查，约束单命令接线、完整批次验证后才登记、只清理新建窗口、显示前取消检查，以及删除必须经过原生关闭确认。这些源码检查不等同于真实 HWND 操作。
- net8 测试项目、完整产品 C# / 原生自测源码的官方 net48 引用程序集编译均为零警告、零错误。
- 标准 VSTest 17.11.1 仍在执行前发生 `TestEngine.ShouldRunInProcess` 内部 NullReferenceException；直接调用结果不能称为标准测试宿主通过。

## 仍开放的债务和验收

| 板块 | 尚未解决 |
| --- | --- |
| 旧格式恢复 / PC-3 | preferred 不完整且无法迁移的数据仍进入 `TryRestoreHostedDockComponentLegacyFallback`，它仍逐窗 Show / SetBounds。需要先将物理恢复输入转换成统一计划，再删除第二条执行路径；本轮没有以删除兼容功能换取行数 |
| Dock 整体顺序 / PC-6 | 普通恢复与 topology 的竞争已增加明确边界；header、resize、restore 尚未统一为整个组的操作序列。特别是已经进行中的 header final 与新展开操作，仍应继续做更细的先后顺序审查 |
| topology 事务 | 组 topology 的占用、规划和重投仍在 Pet partial。普通恢复会取消并替换旧代操作，但没有声称所有热插拔时序已验证 |
| PetForm / PC-7 | 两个 partial 仍有 4142 行，创建、启动恢复、临时重定位、退出和部分事务提交尚未迁出。没有完成整体解耦 |
| 几何 / 成员 / 保存 | 延续前轮实际事实、GroupId/Order 与 single writer 边界；历史字段和其他同步 Save 仍需审查，没有更改磁盘版本 |

原生事务执行期间失败时，沿用已有矩形和可见性回滚；如果原生已成功而 Pet 随后拒绝结果，当前补偿只撤回原本隐藏成员的可见性，并不宣称能无条件恢复所有既有窗口的位置。已结束操作的回调不会再登记会话或提交模型。

取消后已准备的隐藏会话可以由下一次恢复复用；删除会查询原生关闭结果，不以 Pet 登记缺失推断 HWND 不存在。宿主正在故障退出但线程尚未结束时，关闭仍可能被拒绝，需要退出后再试，不能视作已经关闭。

Windows 仍需实际验收：部分可见组展开失败、恢复中收起 / 删除 / 退出、取消后马上重新展开、100% / 150% / 200% 混合 DPI、准备和显示前后热插拔、重建 HWND 的 sequence、IME 编辑关闭拒绝、焦点与 Z-order，以及打包和 306-key 原生自测。PR 保持 draft。
