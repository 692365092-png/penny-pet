# 删除窗口消息中的几何副本，保留实际像素

接续 `8276fbd`，继续处理 PC-3。这个节点收紧跨线程边界，并修复实际窗口事实在接收时
被整数 DIP 回投影改写的问题。

`StickyNoteUiSnapshot` 原先同时支持完整快照和内容快照，携带 14 个位置字段，以及
`_includesPlacement`、两个构造入口、`ApplyTo` 和 `ApplyPreferredTo`。审查实际消费者后，
这些几何数据没有必要：独立窗口通过 `WindowPlacementPlan` 放置，组恢复通过独立的组
计划放置，窗口回执已经携带 `WindowFacts`。Hosted WPF 构造器也使用显式初始逻辑尺寸，
不读取工作副本中的 X/Y/Width/Height；原生可见性兜底读取实际 HWND。

现在删除快照的所有几何字段及两个几何应用入口，只保留一个 `Capture`。新建、恢复、
编辑、拖动、resize 和退出均传相同的内容消息。编辑器工作副本只接收身份、内容和窗口
标志；窗口位置不再从内容消息重建。相同内容从第一次捕获起即可复用，不再为了从
“完整模式”转换成“内容模式”复制一次集合。组恢复的置顶覆盖仍是脱离 canonical 模型的
消息值，改变标志时共享只读条目，不修改已经发出的消息。

同时发现 `StickyPlacementMath.FromPhysicalRect` 将实际像素转换为整数 DIP 后，再用
这些舍入后的值回投影物理字段。125% / 150% / 200% 下，部分坐标和尺寸因此偏移 1 像素，
导致 canonical 的物理副本与 `WindowFacts` 不一致。现在实际像素原样保留，整数 DIP
仅为兼容视图。这个更新不提交或改变持久偏好；用户偏好的提交规则保持独立。

新增 6 个实际接收器回归用例：负屏幕原点、奇数窗口尺寸、三个 DPI，以及普通快照与
批量提交两条路径。断言原始像素精确保留、有效事实仍是同一份捕获、Preferred 未被
改写。另一个用例验证组恢复的置顶覆盖、快照复用和内容集合共享。已有移动/编辑/退出
用例及 Windows 自测改为验证新的内容边界，删除对已移除字段的断言。

验证：557 次实际 MSTest 方法 / DataRow 调用通过，0 失败；Core、测试、Windows Core
和 SelfTests 编译通过，警告视为错误。Windows GUI、真实混合 DPI 拖动和屏幕拔插未在
Linux 上运行。本次不声明实际帧率提升。

PC-3 仍未完全结案：`StickyNoteData` 的物理 / v10 / Preferred 三组字段还在。
跨线程内容边界已不再复制这些状态，下一步需要隔离旧文件的待迁移位置，明确无目标屏
启动和临时恢复行为，才能安全删除运行时兼容字段。
