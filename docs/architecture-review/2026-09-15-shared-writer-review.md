# 设置和便利贴的共享写入机制

基线为用户已经推送的 `282948fc49e9c10e04c5b512cd33d455ffb6f733`。
它与上一轮本地 `66d8724` 的文件树完全一致；五个提交重新应用后哈希发生变化。

本节点处理整体审查中尚未完成的 UI 同步重试问题。

`PetSettings` 原先独立维护 dirty、最后错误和连续失败计数，且每次保存直接执行文件
复制和原子替换。重试定时器先同步保存便利贴，成功后才尝试设置；任一文件卡住都会
阻塞消息循环，便利贴失败还会阻止设置重试。

现有 `StickyNoteWriter` 提取为 `PersistenceWriter<T>`，队列、相邻自动保存合并、
显式请求屏障、revision 和失败通知语义保留。便利贴和设置各持有独立的实例；两个
文件可以独立前进，共用实现不会把它们串成一个全局写入队列。独立紧急导出继续保留。
`StickyWriteRequest` 仍是便利贴领域请求，通用写入器不依赖便利贴或 Windows 类型。

设置在模型线程立即序列化为只读行快照。后台只处理这份快照和存储资源，不枚举可变的
设置或提醒列表。原来三份独立保存状态被移除，属性直接读取写入器状态。16 处不消费
保存结果的常规设置保存改为排队；显式 `Save` / `SaveToFile` 仍返回实际写入结果。
读取旧目录、损坏文件保留和现有设置格式不变。

重试定时器现在分别检查两个写入器：有未保存请求且没有进行中的写入，才提交一次
重试。它不等待磁盘，也不在卡住的写入后不断堆积请求。后续 tick 只有在两个文件都
完成请求后才显示恢复提示。失败通知回到创建设置对象时捕获的上下文；窗口结束后
不再启动重试定时器，较旧失败通知在对应文件已经保存成功时不再显示过期警告。

退出在设置写入器已有请求时也先执行有界 flush，超时进入现有失败处理。退出流程
本身仍含同步屏障及显式最终保存，本节点没有完成整个退出交互的异步改造。

新增五个行为测试覆盖设置快照隔离与合并、失败后的最新数据重试及超时、通知上下文、
两个文件独立前进、真实损坏主文件在替换前保留。原生自测的设置失败检查先等待写入器
通知并处理 UI 消息，不再假定后台通知与同步返回发生在同一个调用栈。

验证：534 次实际 MSTest 方法 / DataRow 调用通过，0 失败；Core、测试及完整 Windows
源码编译通过，警告视为错误。Windows Core 和 SelfTests 也按实际项目源文件分别编译。
标准 VSTest 的环境问题和 Windows GUI/IME/混合 DPI 的运行验证缺口仍然存在。
