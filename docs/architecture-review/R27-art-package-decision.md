# R27 美术包格式评估：保留启动缓存与完整包

结论：本轮不合并格式。已有 indexed PPAP 单包方案能减少体积，但显著拖慢 idle 首次可用时间，并增加启动内存；不满足路线图要求的同时收益。生产读取器、编码器、资源选择、美术与授权文件均保持原状。

## 实验与结果

实现提交 `9b92756`，[Windows CI #171](https://github.com/692365092-png/penny-pet/actions/runs/36516287675)。[原始数据](art-package-benchmark/results-ci-171.json)保留全部 14 次采样、10 个状态的校验摘要、资源哈希与运行来源；[复现说明](art-package-benchmark/README.md)和脚本随仓库保存。

完整 PPAP0003 已支持按 clip 定位和延迟解码。PCAF0003 保存预先渲染为 192×208 的 idle 动画，完整包保存源尺寸帧，需要在加载时转换。实验把未经修改的生产读取/渲染代码编译成双资源和仅 PPAP 两个独立程序，各启动 7 个新进程，交替次序。两者都只使用嵌入资源。

| 指标 | 双资源 | 仅 indexed PPAP |
| --- | ---: | ---: |
| idle 首次可用时间中位数 | 58.47 ms | 334.14 ms |
| 同阶段 CPU 中位数 | 62.50 ms | 328.13 ms |
| 同阶段 private bytes 增量中位数 | 11.25 MiB | 13.85 MiB |
| 同阶段进程 peak working set 中位数 | 33.25 MiB | 38.49 MiB |
| 嵌入资源总量 | 49,033,601 bytes | 48,086,359 bytes |
| 实验 EXE 大小 | 49,072,640 bytes | 48,125,440 bytes |

单包节省 947,242 bytes（0.903 MiB，资源体积约 1.93%），idle-ready 中位数变为 5.71 倍。首次加载只准备 idle，其余状态仍延迟加载。全部 10 个状态的每帧尺寸、帧时长及 premultiplied BGRA（包括透明度）SHA-256 完全一致；重新运行现有编码器得到与 solution build 完全相同的两个资源文件哈希。

这说明预渲染 idle 缓存有可测量作用。删除一个读取器和编码器的维护收益尚不足以抵消当前候选的启动回退，故不采用。

## 证据边界与后续

- 这是同一个 Windows hosted runner 上的新进程/首次 JIT 比较，未清空 OS 文件缓存；不能声称测得物理冷磁盘启动。
- 计时从 `PetArtPackage.Load` 到 idle clip 可用，不含整个进程启动和产品窗口首帧。内存指标为进程值，不能与资源文件尺寸直接等同；完整状态校验阶段的峰值包含哈希工作。
- 本轮排除的是“删除 PCAF，仅保留当前 PPAP”的具体候选，不是证明所有未来单包布局都会慢。若以后设计单格式中保留预渲染 idle，必须另测不同画布/渲染设置、体积、构建重复性和维护成本，不能引用本轮数据当作通过。
- 正式 EXE 与开发资源路径仍由现有验证覆盖，CI #171 的 597 项测试、原生窗口自测、正式单文件 EXE 冒烟、Dock 基线、美术校验及产物检查全部通过。
- 该实验保留为手动 CI/本地工具，普通 PR 不再重复运行全部采样和资源重编码。性能数值不成为容易波动的 CI 阈值；手动实验仍严格检查来源、像素/时长一致和构建可重复性。

R27 条件评估到此结束。后续重点是已记录的真实 IME、物理多屏及旧客户端数据验收；R26 的格式退役条件不因 R27 完成而改变。
